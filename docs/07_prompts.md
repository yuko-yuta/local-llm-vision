# Gemma4 画像認識Webアプリ - プロンプト設計

## 1. 通常画像認識プロンプト

`/api/vision/analyze` で使用。

```
この画像を日本語で分析してください。

以下の形式で回答してください。

【画像の概要】
画像全体に何が写っているか

【認識した物体】
箇条書きで記載

【認識した文字】
画像内に文字がある場合のみ記載

【補足】
気づいた点があれば記載
```

### 設計意図

- 構造化された回答形式を指定することで、表示UIと対応させやすくする
- 「文字がある場合のみ」と明示することで不要な「文字なし」コメントを抑制
- 日本語指定で応答言語を固定する

---

## 2. リアルタイムOCRプロンプト

`/api/vision/ocr` で使用。

```
この画像内に写っている文字だけを抽出してください。

ルール:
- 文字がない場合は空文字を返してください
- 説明文は不要です
- 推測しすぎないでください
- 読み取れる文字のみ返してください
```

### 設計意図

- 2秒ごとに高頻度で実行するため、レスポンスは最小限にする
- 説明文を禁止することで後処理（差分比較）を簡単にする
- 「推測しすぎない」を明示して誤認識を抑制する
- 空文字を返す条件を明示して「文字なし」の表現を統一する

---

## 3. プロンプト改善の方向性

### OCR精度を上げたい場合

```
この画像に写っているすべての文字を、見えたままに書き出してください。

- 文字が読み取れない場合は空文字を返してください
- 行の区切りは改行で表現してください
- 装飾・説明・補足は一切不要です
```

### 領収書・レシート特化の場合（将来拡張）

```
この画像はレシートまたは領収書です。以下の情報を抽出して、JSON形式で返してください。

{
  "store_name": "店舗名",
  "date": "日付 (YYYY-MM-DD形式)",
  "total": "合計金額 (数字のみ)",
  "items": [{"name": "商品名", "price": 金額}]
}

情報がない場合はnullを使用してください。
```

---

## 4. プロンプト調整時の注意点

- Gemma4はモデルの特性上、プロンプトが短いほど速い
- OCRループでは特に速度を優先し、プロンプトを最短にする
- 日本語指定がない場合、英語で返ってくることがあるため必要に応じて明示する
- 「JSON形式で返してください」などの構造化指示は、通常プロンプトより処理が重くなる場合がある
