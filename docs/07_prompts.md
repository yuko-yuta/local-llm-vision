# Local LLM Vision - プロンプト設計

## 1. 通常画像認識プロンプト

`/api/vision/analyze` で使用。

```
この画像を日本語で分析してください。

以下の形式で回答してください。

【画像の概要】
画像全体に何が写っているか

【認識した物体】
箇条書きで記載

【認識した文字】
画像内に文字がある場合のみ記載

【補足】
気づいた点があれば記載
```

### 設計意図

- 構造化された回答形式を指定することで、表示 UI と対応させやすくする
- 「文字がある場合のみ」と明示することで不要な「文字なし」コメントを抑制
- 日本語指定で応答言語を固定する

---

## 2. リアルタイム OCR プロンプト

`/api/vision/ocr` で使用。

```
この画像内に写っている文字だけを抽出してください。

ルール:
- 文字がない場合は空文字を返してください
- 説明文は不要です
- 推測しすぎないでください
- 読み取れる文字のみ返してください
```

### 設計意図

- 2 秒ごとに高頻度で実行するため、レスポンスは最小限にする
- 説明文を禁止することで後処理（差分比較）を簡単にする
- 「推測しすぎない」を明示して誤認識を抑制する
- 空文字を返す条件を明示して「文字なし」の表現を統一する

---

## 3. 名刺データ抽出プロンプト

`/api/vision/card` で使用。出力は厳格な JSON のみを期待する。

```
この画像は名刺です。以下のJSON形式で情報を抽出してください。
読み取れない項目は空文字にしてください。
説明文・コードブロック・余分な文字は不要です。JSONのみ返してください。

抽出ルール:
- "department" は「○○部」「○○課」「○○本部」「○○室」など組織の所属を表す表記を抽出する
- "title" は「課長」「マネージャー」「Director」など役職を表す表記を抽出する
- "companyUrl" は会社のWebサイトURL（http(s)://～）を抽出する。@ で始まるメールアドレスは含めない
- "tel" は会社固定電話（TEL）を抽出する
- "mobile" は携帯電話（Mobile・携帯・Cell）を抽出する
- "fax" は FAX 番号を抽出する

住所の抽出ルール:
- 郵便番号・都道府県・市区町村・番地・号をすべて含めること
- ビル名・建物名・タワー名が記載されている場合は必ず含めること
- 階数（○F・○階）が記載されている場合は必ず含めること
- 部屋番号・号室が記載されている場合は必ず含めること
- 住所に関する情報は一切省略せず、名刺に記載された文字をそのまま抽出すること

{
  "name": "氏名（漢字）",
  "nameAlphabet": "氏名（アルファベット）",
  "nameKana": "氏名（ふりがな・カタカナ）",
  "company": "会社名",
  "department": "部署名",
  "title": "役職・肩書",
  "companyUrl": "会社のWebサイトURL",
  "address": "郵便番号から始まる完全な住所（ビル名・階数・部屋番号を含む）",
  "email": "メールアドレス",
  "tel": "会社の電話番号（TEL）",
  "fax": "会社のFAX番号（FAX）",
  "mobile": "携帯電話番号（Mobile・携帯）"
}
```

### 設計意図

- **構造化抽出**: 12 項目を固定キーで取得することで、フロント側の `BusinessCardData` と 1:1 で対応させる
- **空文字フォールバック**: 未記載項目は空文字。`null` 等を返されると JSON.parse 後の取り回しが面倒なため文字列に統一
- **JSON のみ**: 解説文や Markdown コードブロックが付くケースに備え、サーバー側パーサ (`parseCardJson`) でも前後のテキスト除去 + 最長一致の `{...}` 抽出を行うが、まずプロンプトで抑止する
- **TEL / Mobile / FAX の区別**: 出力後に電話番号の用途が分からなくならないよう、種類を明示してから抽出させる
- **住所は省略禁止**: ビル名・階数・部屋番号は名刺認識でよく欠落する箇所のため、特別にルールを並べて落とさせない
- **会社 URL とメールの混同防止**: モデルが `mailto:` を URL として返すケースを抑制するため「@ で始まるメールは含めない」と明示
- **QR コードは扱わない**: gemma4 は QR コードの画像復号ができないため、URL 系項目は印字テキストのみを対象とし、ユーザーがフロントで手入力できる前提

---

## 4. プロンプト調整時の注意点

- Gemma4 はプロンプトが短いほど速い。OCR ループ系はとくに短さ優先
- 日本語指定がない場合、英語で返ってくることがあるため必要に応じて明示する
- JSON 出力指示は通常プロンプトより重くなる傾向。名刺モードは 3 秒間隔と長めにしているのもこのため
- 出力フォーマットを変更する場合は、フロントの型 (`BusinessCardData`) と CSV カラム (`CSV_COLUMNS`) も合わせて更新する
