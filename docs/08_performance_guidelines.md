# Local LLM Vision - パフォーマンス方針

## 画像サイズ最適化

| 用途 | 最大幅 | JPEG 品質 | 理由 |
|---|---|---|---|
| 通常認識（アップロード） | 1024px | 0.8 | 精度重視 |
| 通常認識（カメラ手動撮影） | 1024px | 0.8 | 精度重視 |
| 通常認識（リアルタイム OCR） | 640px | 0.7 | 速度重視 |
| 名刺モード（手動撮影） | 1024px | 0.8 | 精度重視 |
| 名刺モード（自動スキャン） | 800px | 0.85 | OCR とのバランス（細かい文字を残しつつ間隔に間に合う） |

## ループ設定

| モード | 間隔 | クライアントタイムアウト | 同時リクエスト | 失敗時の挙動 |
|---|---|---|---|---|
| 通常認識・リアルタイム OCR | 2 秒 | 15 秒 | 最大 1 件 | 連続 3 回失敗で停止 |
| 名刺・自動スキャン | 3 秒 | 60 秒 | 最大 1 件 | 連続 3 回失敗で停止 |

サーバー側 `ollama.ts` のタイムアウトは独立で **60 秒固定**。クライアント側のタイムアウトはどちらも UI が固まらないよう短めに切ってある。

## PC 負荷を下げるための工夫

1. **前ループが完了するまで次のリクエストを送らない**
   - `isScanRunningRef` で制御
   - `setInterval` + `useRef` フラグの組み合わせ（state だと async タイミングで取りこぼす）

2. **画像を縮小してから送信**
   - Canvas API で `maxWidth` にリサイズしてから base64 化
   - Ollama への転送データ量を削減

3. **前回と同じ結果なら画面更新しない**
   - 通常モード OCR: 前回文字列との比較
   - 名刺モード: 前回 JSON 文字列との比較
   - React の不要な再レンダリングを防ぐ

4. **編集中は新規スキャン結果を捨てる（名刺モード）**
   - `hasCardDataRef.current === true` の間は自動スキャン結果を破棄
   - ユーザーが手入力中の値を 3 秒間隔で上書きされる事故を防ぐ

5. **カメラ停止 / モード切替時にループを止める**
   - `useEffect` の cleanup と `stopCamera()` で `clearInterval`
   - バックグラウンドでの無駄なリクエスト送信を防ぐ

6. **連続エラーで自動停止**
   - 同一ループで `OCR_MAX_CONSECUTIVE_ERRORS (=3)` 回連続失敗するとループを止め、メッセージを出してカメラ再起動を促す
   - 暴走 fetch でブラウザがフリーズする事故を防ぐ

7. **`AbortSignal.timeout` の互換ラッパー**
   - iOS Safari 17.3 以前は `AbortSignal.timeout` 未サポートのため、`AbortController` + `setTimeout` でフォールバック

## Ollama・Gemma4 のスペック目安

| 環境 | 1 回の認識時間目安 |
|---|---|
| GPU (RTX 3060 以上) | 1〜3 秒 |
| CPU (Core i7 相当) | 5〜15 秒 |
| CPU (低スペック) | 30 秒以上 |

- CPU 環境では 2 秒間隔の OCR は重すぎる場合がある → 3〜5 秒に調整推奨
- 名刺モードは JSON 抽出のため通常 OCR より重い。3 秒間隔・60 秒タイムアウトに設定済み
- 間に合わない場合: 「前のリクエストが完了するまで次は送らない」設計のため、実効間隔は自動的に広がる

## 画像サイズと base64 の関係

| 元画像 | 縮小後 | base64 サイズ概算 |
|---|---|---|
| 4K (3840x2160) | 1024px 幅 | 約 200〜400KB |
| FHD (1920x1080) | 1024px 幅 | 約 150〜300KB |
| 名刺自動スキャン | 800px 幅 | 約 100〜250KB |
| 通常 OCR 用 | 640px 幅 | 約 50〜150KB |

小さいほど Ollama への転送・推論が速くなる。

## メモリと保存データ

- 保存済み名刺は React `useState` のみ。リロード / タブを閉じると消える
- 1 件あたり数 KB 程度なので数百件保存しても実用上の負荷は無視できる
- ページ離脱時は `beforeunload` で確認ダイアログ。CSV ダウンロードで保全する想定
